# One observable request: abstraction contract

Question: for one isolated request, what changes when an assumed-compatible
remote prefix is retrieved rather than recomputed? Rates can be changed to inspect
the arithmetic. This is a conditional model, not a real-device timing predictor.

## Visuals and ontology

The scene has one request and an inference system with a single execution
resource, an optional state artifact and residency,
a transfer link, and output completion events. Each selectable object names its
[canonical ontology term](../ontology/inference.md). The generator reads definitions
from that document for both the inspector and linked ontology page. Ontology
entries link back to the corresponding visual objects.

Chat, Agent, and App are mutually exclusive caller labels for the same single
invocation. They do not imply distinct service rates, autonomous behavior, or
simulated agent tool loops. Routing, contention, queues, batching, and multiple
workers have been removed from this teaching scenario. The previous concurrent
scenario is superseded rather than retained as a hidden execution path.

Selecting the inference system opens its numerical integration boundary.
The separate [naïve GPT instrument](naive-gpt.md) now executes the model path. Tokenizer,
embedding, transformer layers, output projection, token selection, and
detokenizer each link to canonical definitions. These stages have no computed
values in the current experiment. The system boundary also includes serving
policies, state placement, and execution resources; it is not synonymous with
a worker. Only the three existing controls affect the executable model today.

## Numerical integration boundary

The numerical GPT emits observations from its actual execution:
input bytes, token IDs, embeddings, layer tensors, retained state, logits,
selected tokens, and decoded output. Connect those observations to request and
work-item identities, positions, and layers as applicable. Cost simulation should
consume identified work and resource demands under explicit assumptions; the
renderer consumes traces. Neither should independently recreate model outputs.

Before connecting the timing model, revise its work/state mapping against that
execution: prompt processing yields the first next-token logits, while feeding
a selected token advances the retained state for the next prediction. The
current fixed output steps are abstract accounting, not those GPT operations.
Do not reuse the current one-unit-per-output rule as a KV-cache invariant.

Integration evidence must include tokenizer round trips, independent forward
calculations, causality, cached-versus-recomputed equivalence, and trace fidelity.
Simulation validity still requires separate evidence for each claimed cost or
system consequence. The coupling described here remains an integration contract; the numerical
backend exists separately and does not validate this cost model.

## Model mapping

Input positions and output length are supplied, not generated by a language model.
A fixed delivery event is followed by a worker reservation sufficient for this
bounded run. Reuse optionally restores an already-warm, compatible prefix;
compatibility and state contents are assumptions, not verified results here.
Prefill handles the uncached input. Decode consists of fixed output steps, then
active state and its reservation are released. The remote artifact is retained.

Each event records its prerequisites, time interval, equation with operands,
explanation, and state before/after. Ready state, reserved capacity, and delivered
output count are distinct. Readiness changes atomically at completion of each
modeled work item. Fractional progress bars do not imply fractional state readiness.
Final decoding and release share a time boundary; their separate event records
remain inspectable. Output delivery has zero modeled return-network delay.

Transfer costs setup plus state size divided by transfer rate. Prefill costs
uncached input work divided by compute rate. Decode costs the larger of its
compute demand and a fixed memory-service floor, assuming perfect overlap within
that step. Other phases serialize. Exact settings live in inside_inference/labs/journey.py and
are exported with each run. State units are abstract accounting units, not bytes.
An output marker is one abstract output step, not computed text or verified KV.

## Comparison and validity

Change one control and replay the same request. The displayed completion reference
is explicitly the original no-reuse, rate-2 baseline. A caller-label change leaves
all modeled work unchanged. Compute and bandwidth are assumptions with no hardware
calibration. Named storage devices are not represented by this experiment.

Independent hand calculations verify phase durations and crossover cases. Tests
verify prerequisite order, state continuity, bounded reservations, atomic readiness,
output counts, release, deterministic replay, and explicit failure for insufficient
capacity. Browser checks verify that event selection and object inspection show
the generated evidence rather than a second calculation invented by the renderer.

These checks establish consistency with the specified isolated arithmetic model.
They do not establish that it predicts a particular real system. The abstraction
is suitable for inspecting conditional dependencies and arithmetic, not for
establishing a production routing policy or a universal cache benefit. Cache
correctness requires a separate numerical model comparison. Real timing claims
require applicable measurements beyond calibration cases.

Omitted effects include local retention, overlap between phases, variable lengths,
shape-dependent kernel efficiency, changing decode memory demand, concurrent work,
and cache misses. They can reverse an apparent benefit outside this question.

## Execution and presentation

Python generates a bounded grid of 18 scenarios at build time; the browser replays
their events locally. One scenario has seven or eight events, including release.
No request workload or model computation is secretly running behind the animation.
The UI states that the complete schedule is precomputed. The visible phase list,
equations, state transitions, and downloadable trace expose that schedule.

Changing playback speed affects presentation only. Changing any control resets
the run. Browser and host feasibility measurements must identify this version;
the earlier multi-request measurements do not apply automatically.
